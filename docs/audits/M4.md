## 0. Verdict

**Gate decision 2026-11-20 (owner): PASSED.** 4.1 to 4.11 pass in the VM (4.3 as amended for R-37, 4.6 with `doctor_ext.txt`, 4.7 with `tests/results/evidence/m4-gate/finder/2026-11-20/`); this audit is signed with F-01 fixed. F-02 to F-06 are Low and stay open as non-blocking follow-ups. Items the VM cannot show (real USB insertion) go to M5 hardware validation (T-M5-10). The auditor's verdict follows unchanged.

**PASS with one caveat (one Medium finding; no Critical, no High).** All four acceptance clauses hold as written, with the single exception that the "disk-derived strings are only ever data" guarantee of ARCHITECTURE §6 is incomplete for the notification path: a volume label that begins with `-` reaches `osascript` as an argument that `getopt` parses as an **option** (F-01, Medium). The practical effect is a suppressed notification (the helper exits with a run-handler conflict), not demonstrated code execution, but the invariant is breached and the fix is two lines. Everything else — the worker argv builder and `argv_check()`, the option allow-list, the mount-point and journal path construction, the two-door `journal_clear`/`repair` authorization, and the probe-string handling into names and terminals — behaves as specified and fails closed.

**Status 2026-11-19: F-01 is fixed** in the commit that adds this audit: a leading `-` in a label becomes `_` (`src/sanitize/label.c`, `U-LABEL-03`, the test oracle), and the notification helper passes `--` before the text (`notify.c`). With that, all four clauses hold without caveat. F-02 to F-06 stay open as Low.

## 1. Acceptance clauses

### Clause 1 — no client or disk input reaches a root-executed string

**Holds, with caveat F-01.** Every `execve`/`posix_spawn` in the daemon was traced:

| Sink | argv / path source | Verdict |
|---|---|---|
| probe / volmark (`spawn.c:1176`, `:1319`) | program path is a fixed manifest constant (`NTFSMAC_PATH_PROBE/VOLMARK`); args are `--fd <int>`, and for volmark `--expect-serial %016PRIX64` / `--expect-sectors %PRIu64` formatted from integers (`spawn.c:1308-1311`) | data-free |
| worker (`spawn.c:1619` via `launch`) | argv from `ntfsmac_options_build()` (literals + console uid/gid + device fd), re-checked by `ntfsmac_argv_check()`; the leaf is the sanitised label, a **separate** argv element, never in the option string (`options.c:55-101`, `argv_check.c:230-231`) | data-free |
| `sandbox-exec` wrapper (`spawn.c:750-805`) | tool path fixed; `-p <profile text>` read from a root-owned, non-group/other-writable, `O_NOFOLLOW` file ≤32 KiB (`profile_read`, `spawn.c:650-688`); `-D` params are `EXEC_PATH` (`realpath` of the fixed program), `CTL_SOCKET`/`CTL_SOCKET_REAL`/`XPC_SERVICE` (compile-time constants), `USERMAPPING_PATH` (fixed) and `USERMAPPING=yes/no` | data-free |
| `launchctl asuser <uid> <self> --exec-as <uid> <gid> <prog> …` (`spawn.c:826-895`) | uid/gid are integers; `<self>` from `_NSGetExecutablePath`; `--exec-as` rebuilds a 2-entry env (`PATH=…` plus a syntactically validated `NTFSMAC_ERRFD=<≤4 digits>`), discarding launchd's additions (`spawn.c:869-905`) | data-free |
| notification helper (`notify.c:187-199`) | `/bin/launchctl asuser <uid> /usr/bin/sudo -n -u #<uid> /usr/bin/osascript -e … -e "end run" <text> <title>`; `<text>` built from a fixed template + the sanitised label (`ntfsmac_notify_text`) | **F-01** |

The worker option string is produced only by `options.c` (string literals and two integers) and independently re-parsed by `argv_check()`, which enforces byte range `0x21..0x7E` with no `\`, the key allow-list, per-key grammars, the mandatory Always set, and a banned list that includes `recover`, `remove_hiberfile`, `fsname`, `rdonly`, `dev`, `suid`, `allow_root`, `efs_raw` and the useless keys (`argv_check.c:39-47`, `:242-266`). No disk or client byte can enter it; confirmed by reading the builder and the validator. See Clause-4 for the one place a disk string does reach a command argument (F-01).

Client control is confined to `bsd`, `mode`, `force`, `action`, `confirm_label`, `confirm_serial`, `auth` — all validated and compared, never used to build a command (`ctl_parse.c:48-60`, `:510-548`). `bsd` is checked against `disk[0-9]+(s[0-9]+)?` before it becomes `/dev/<bsd>` (`session.c:98-106`, `ctl_parse.c:336`).

### Clause 2 — no root file operation outside `/Volumes` or the journal directory

**Holds.**
- Mount point: `ntfsmac_mountpoint_create` fixes the parent to `/Volumes`, opens it `O_RDONLY|O_DIRECTORY|O_NOFOLLOW`, verifies owner, and `mkdirat`s a leaf that contains no `/` (sanitiser allow-list) relative to that descriptor; all later work is on the returned descriptor, and removal re-checks dev+ino under `O_NOFOLLOW`/`AT_SYMLINK_NOFOLLOW` (`mountpoint.c:33-189`, `leaf.c:24-73`). The worker's mount-point argument must start with `/Volumes/` or the spawn is refused (`spawn.c:1548-1552`).
- Journal: all opens/renames are `openat`/`renameat` relative to a `O_DIRECTORY|O_NOFOLLOW` directory descriptor; file names are formatted only from the 16-hex serial and a UTC stamp, never from probe text (`journal.c:120-160`, `:734-762`, `:884-910`). Removal renames into `cleared/` inside the same tree.
- Other root opens are fixed paths with `O_NOFOLLOW`: the control socket, the code-requirement file (`ctl_sys.c:186`), macFUSE plists for `doctor` (`doctor.c:134`), sandbox profiles (`spawn.c:672`). Unmount targets are `/Volumes/<leaf>` (daemon-made) or, for a stray FUSE mount, a user-owned path unmounted **as the user** so the kernel's `f_owner` check bounds it (`mountwatch.c:263`, `:355-389`; ARCHITECTURE §6 "Teardown").

### Clause 3 — `journal_clear`/`repair` unreachable without the ADR-019 checks

**Holds.** Both commands are rejected on the Unix socket with `wrong_channel` before any check or work (`ctl.c:160-166`), and the XPC door serves nothing else. On XPC, `handle_message` runs `ntfsmac_xpc_check_request` (one request, right command, no newline/NUL), reads the sender's audit token per message, builds the peer from it, then `ntfsmac_ctl_handle_line_env` applies the gate and, for a privileged command, `ntfsmac_ctl_authorise_privileged` → check 1 (admin), check 2 (not a spawned process / descendant), check 3 (signed CLI, hardened runtime; also enforced at connection level by `xpc_connection_set_peer_code_signing_requirement`), check 4 (`ROOT_PEER` in the product: audit-token euid 0) before `run_op` dispatches to the operation (`ctl_xpc.c:93-139`, `ctl.c:161-178`, `ctl_peer.c:270-293`). The operation then re-runs check 5 (`volume` present, fresh probe passes the §3.2 gate, typed label+serial match a fresh probe) in `ntfsmac_policy_gate_journal_clear` / `_gate_repair` / `_gate_sync_mirror` (`ctl_journal.c:148-245`, `policy.c:146-237`). The gates are fully fail-closed: `verdict_is_clean` now also requires `is_ntfs`, `!bitlocker`, `has_ntfs_version`, clean log, absent/inactive hiberfile and only informational volume flags (`policy.c:43-54`, the M3 F-04 hardening). No code path reaches `ntfsmac_priv_journal_clear`/`_repair`/`_repair_mirror` except through `run_op` after `authorise_privileged` passed; `in.peer_authorised` is hard-set only because the four checks already ran (`ctl_journal.c:189`). The XPC listener refuses to start without a readable requirement file (`ctl_xpc.c:170-176`), so check 3 is never silently skipped. The `--exec-as` entry point and the config seam cannot weaken check 4: the strategy is fixed at compile time and only `main.c` copies the default into the env (ARCHITECTURE §3.4; `ctl_peer.c:208-213`).

### Clause 4 — probe strings never reach a file name or a terminal

**Holds for file names; holds for terminals with caveat F-01.**
- File names: journal entry/temp/tombstone names come only from the parsed 64-bit serial (`journal.c:120-160`); `serial`/`logfile_lsn` are used as integers; the mount leaf is the output of `ntfsmac_label_sanitize`, a strict-UTF-8 allow-list (ASCII `A-Za-z0-9 -_.()+` and a Unicode-15.1.0 generated deny table), with a leading dot/mark replaced and an `NTFS-<serial>` fallback (`label.c`, `label_cp.c:88-97`). No probe byte reaches a name.
- Terminal: the CLI renderer escapes every control byte, DEL, C1, bidi/invisible control and invalid UTF-8 as `\xNN` (`render.c:68-99`); `nonnfc_paths` are reduced to `\u{…}`/`\x{…}` ASCII by `ntfsmac_path_display` inside the daemon before they enter the `status` JSON (`display.c`, `report.c:198-210`); reason codes travel as enums the CLI maps to its own text. The notification text strips control bytes (`put_safe`, `notify.c:46-56`). The one gap is that the sanitised label — though free of control/quote/colon/comma/slash bytes — may begin with `-`, which `osascript`'s argument parser treats as an option (F-01).

## 2. Findings

### Medium

**F-01. A volume label beginning with `-` is parsed by `osascript` as an option, defeating the "label is only data" guarantee of the notification path** (`src/daemon/notify.c:187-199`; `src/sanitize/label.c:66-98`; `src/common/label_cp.c:88-97`).
The banner helper runs, in the console user's session:
`… /usr/bin/osascript -e "on run argv" -e "display notification (item 1 of argv) with title (item 2 of argv)" -e "end run" <text> <title>`
with the attacker-influenced `<text>` as a positional argument, intended to arrive as `item 1 of argv` (data). The label sanitiser allows `-` as an interior **and leading** byte: it strips leading spaces and turns a leading `.` or combining mark into `_`, but does nothing to a leading `-` (`label.c:66-83`; `-` is on the allow-list, `label_cp.c:92`). For a volume labelled e.g. `-e beep`, `ntfsmac_notify_text` yields `"-e beep is mounted read/write."`, and because the argument begins with `-e`, `osascript`'s `getopt` consumes it as an additional `-e <statement>` rather than as `argv`. Verified against stock `/usr/bin/osascript`: a text argument beginning with `-e …` is taken as an option (error `-2752`, "run handler specified more than once"); prefixing the positional arguments with `--` makes the same text return as `item 1 of argv`. This is reachable from a plugged-in USB volume: every `MOUNTED_RW/RO`, `REFUSED`, `SESSION_UNCLEAN` notification uses the label as the leading `%s`.
Impact, assessed: the injected trailing template (`… is mounted read/write.`, `… was not mounted: …`) contains `/`, `:` or `.` and the injected statement lands *after* the real `on run / end run` handler, so a command-type payload triggers the run-handler-conflict error and the helper exits non-zero — the notification is **suppressed**, not executed. Code execution would require the injected `-e` text to form a handler-free valid script despite the trailing template; I did not find a way and did not demonstrate one (the guillemet trick `do shell script («data utf8…»)` avoids quotes but still conflicts with the existing run handler and is broken by the trailing `/`). So the realistic effect is loss of the user-facing warning for exactly the hostile-volume case the design is built around, plus a clear breach of the §6 claim that disk strings are "only ever data." Severity Medium on the breach + warning-suppression; not ranked High because reliable execution is not shown.
Fix (two lines, no behaviour change for normal labels): insert a literal `--` argv element between the last `-e` and `<text>` in `banner_thread` (`notify.c:191-199`), so `osascript` stops option parsing; defence-in-depth, also map a leading `-` to `_` in `ntfsmac_label_sanitize` as is already done for a leading `.`. Add a label fixture beginning with `-e` to the notify text test and an integration check.
Status: verified by reading the sink and the sanitiser, and by exercising stock `osascript` with innocuous inputs; code-execution reachability investigated and not demonstrated.

### Low

**F-02. `device_free` kills any console-user process holding the volume's device node by dev+ino, including an unrelated reader** (`src/daemon/spawn.c:514-547`, `:428-449`). After the worker exits, every process of the console user whose vnode matches the device's `st_dev`/`st_ino` is `SIGKILL`ed. This is the intended orphan-descriptor sweep, but a benign user process that merely opened `/dev/diskNsM` (e.g. `lsof`, `hdiutil`, a disk utility) between worker exit and the sweep would be killed too. No privilege escalation (only the console user's own processes, never the daemon), so Low; worth a comment and, if cheap, narrowing to writable descriptors.

**F-03. `usermapping` file is `lstat`-checked by the daemon, then opened by the worker — a check/use gap** (`src/daemon/spawn.c:1492-1498`, `:1577`; profile allows `file-read` of the literal path). `usermapping_file_ok()` validates the fixed root-owned path, and the worker later opens it itself. The window is only exploitable by root (the containing directory is root-owned, ancestors verified at install, `dev-install.sh:134-152`), so Low / defence-in-depth; note that the real guard is the directory ownership, not the daemon's pre-check.

**F-04. `ROOT_PEER` reduces check 4 to "audit-token euid == 0"** (`src/daemon/ctl_peer.c:218-226`; ARCHITECTURE §3.4, U17). This is the deliberate post-U17 product choice (`sudo ntfsmac …`): a privileged request needs an admin peer that is the signed CLI, not a spawned process, and root. A root process that is *also* the installed hardened CLI could issue the request without a fresh password prompt, but root already has full control, so this is the accepted trade-off, not a defect. Recorded here only because the audit must state it; the `auth` field is accepted and ignored under this strategy, as documented (`ctl_peer.c:222-224`).

**F-05. The notification helper depends on root's sudoers allowing `sudo -n -u #<uid>`** (`src/daemon/notify.c:188-192`). If the policy denies it, the banner silently fails (the thread reaps/kills the helper and returns). No security impact (fail-closed to "no notification"), Low; worth a `doctor` note so a missing banner is diagnosable.

**F-06. Stale-socket replacement has a small TOCTOU** (`src/daemon/ctl.c:432-444`). `bind_socket` `lstat`s the path, confirms it is a socket and refused-on-connect, then `unlink`s and `bind`s. The directory is `/var/run` (root-only), so only root can race it; Low. The code already refuses to remove a non-socket and never removes a file its own bind did not make.

No finding shows a path by which client or disk input reaches a root-executed command string (F-01 reaches an `osascript` argument run **as the console user**, not root), escapes `/Volumes`/the journal directory, injects a banned or disk-derived mount option, or reaches `journal_clear`/`repair` without the ADR-019 checks.

## 3. Checks requested by the task

- **TOCTOU on paths/device nodes:** mount-point create/remove re-verify dev+ino under `O_NOFOLLOW`; journal uses `openat`/`renameatx_np(RENAME_EXCL)`; session binding re-reads block 0 and dev-identity through a fresh descriptor after every step (`session.c:446-650`). The only residual windows are F-03 and F-06 (root-only). Holds.
- **fd inheritance:** `POSIX_SPAWN_CLOEXEC_DEFAULT` plus explicit `addinherit_np` for 0–2 and the named keep set (device fd, and for the worker the errwatch write end); the Linux test path closes every other fd (`spawn.c:964-1001`). The errwatch pipe and the control pipes are `FD_CLOEXEC` (`errwatch_io.c:40-56`, `spawn.c:189-206`). No stray descriptor reaches a child. Holds.
- **signal/kill scope / pid reuse:** children are peeked with `waitid(…WNOWAIT)` so the zombie leader keeps the pgid reserved while the group is killed (`spawn.c:166-180`, `:1636-1660`); `kill_tree`/`kill_group_of` never signal pid ≤ 1 and stop each descendant before killing (`spawn.c:462-508`). `device_free` kills by exact dev+ino, so a reused pid is only hit if it genuinely re-opened the same device (then killing is correct) — see F-02 for the benign-reader edge. Holds.
- **integer/length bounds on parsed records:** the errwatch grammar caps the line at `NTFSMAC_ERRWATCH_LINE_MAX`, records at 64, errno digits at 5 (≤99999), count digits at 10 (≤INT_MAX), and rejects leading zeros, non-0x20..0x7E bytes and bytes after EOF (`errwatch.c:30-187`). The ctl parser bounds every field's decoded length (`ctl_parse.c:48-60`) and the volmark/probe runs bound `total_sectors ≤ 0x7fff…` and fd range (`spawn.c:1299-1301`, `:1167`). Holds.
- **format-string use:** every `printf`/`snprintf`/`vsnprintf` uses a constant format; untrusted text is always an argument, never the format (`report.c:57` `vsnprintf(fmt)` is reached only with literal formats; `log.c:76`; `notify.c`; `render.c`). JSON output escapes quote/backslash/control (`report.c:66-85`). Holds.
- **product preset has no test seams:** `NTFSMAC_TEST_SEAMS=OFF`, `NTFSMAC_AUTHZ_FALLBACK_ROOT=ON` in the `product` preset (`CMakePresets.json:18-25`); the seam fields and the `--socket/--journal-dir/--child-log/--no-marker/--console-uid` options compile out under it (`main.c:88-104`, `:2107-2119`; `spawn_config.h:112`), and `dev-install.sh` refuses a build whose strings or `--bogus` usage line show any seam and verifies the two CMake values (`dev-install.sh:200-227`). Holds.
