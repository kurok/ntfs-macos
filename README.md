# ntfs-macos

Native NTFS read/write support for macOS 27 and newer, built on mature open-source
components (NTFS-3G on the macFUSE FSKit userspace backend) rather than a from-scratch
filesystem.

> **Status: developer preview, VM-verified only, not production-ready.** Milestones 1 to 4 and 6
> are done, and milestone 5 is done except its performance report: the daemon mounts NTFS volumes
> read/write (read-only when a volume is dirty, hibernated or unknown), the `ntfsmac` command and
> Finder work, and the release package installs, upgrades and
> uninstalls cleanly. Everything is tested in macOS virtual machines on disk images; it has not been
> run against real USB drives yet (`docs/HARDWARE_TEST_PROTOCOL.md`). Milestone 7 (release
> readiness) has started. Do not use this on a drive that holds data you care about.

No current package is published. The only published package, the pre-release
[`0.1.0-dev.20261116`](https://github.com/kurok/ntfs-macos/releases), is superseded: do not install
it ([release notes](docs/releases/0.1.0-dev.20261116.md) say how to remove it). Packages are built
and tested locally (ADR-015); to build one, see "Build from source" in
[docs/INSTALL.md](docs/INSTALL.md). From the next release on, a release package's `SHA256SUMS` is signed with
the release key in [packaging/release-signers](packaging/release-signers).

## Goals

- Read/write NTFS on macOS 27+, Apple Silicon first, Intel where feasible
- Finder integration and standard mount/unmount, removable drives
- Conservative safety: read-only fallback for dirty, hibernated (Fast Startup) or unknown volumes
- No SIP changes, no replaced system binaries, minimal kernel involvement

See [docs/PROJECT_BRIEF.md](docs/PROJECT_BRIEF.md) for the full brief, milestones and
definition of done. Progress is tracked in [CHECKPOINT.md](CHECKPOINT.md) and
[NEXT_ACTIONS.md](NEXT_ACTIONS.md).
