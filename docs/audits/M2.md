### Medium

**F-01. The result-file rules do not fit the way M2 gate evidence is produced and committed (TEST_STRATEGY section 10, 4.2).**
(a) `I-SMOKE-01` and `I-SMOKE-02` are registered as M2 cases in TEST_STRATEGY 4.2 and named by criteria 2.2 and 2.6, but they are shell scripts outside the harness (`tests/harness/run.py --list` cannot run them). I produced a schema-valid file by hand (section 1); a harness adapter (`run.py --cases I-SMOKE-01`) should replace that before M3 relies on these cases.
(b) Section 10 allows a gate commit G to be covered by a result with `git_sha` an ancestor of G only if `git diff --name-only <git_sha> G` lists nothing but `tests/results/`, `CHECKPOINT.md`, `NEXT_ACTIONS.md` and the README status table. Committing this audit adds `docs/audits/M2.md`, and the gate normally also edits `docs/IMPLEMENTATION_PLAN.md` and `docs/AGENT_TASKS.md`. Strictly, no commit that records the audit can then be covered by results at `00abf04`. Either add `docs/audits/` (and the plan and task status tables) to the allowed list, or let the gate verdict commit change only the listed paths and put the audit note in a commit before the results. `scripts/ci-local.sh --verify-result` does not exist yet (T-M5-08), so nothing enforces the rule meanwhile.

## 5. Patch 0003 (high level)

`patch -p1 --dry-run` applies cleanly to the pinned 2026.9.28 tree (4 files). Read against `libntfs-3g/unix_io.c` and `src/ntfs-3g.c` of that tree:

- The parser accepts only `/dev/fd/N`, N >= 3, no leading zero, and only if `fcntl(F_GETFD)` says N is open; every other name takes the upstream path.
- Error paths: the new `goto err_out` branches run before `d_private` holds a descriptor; `err_out` frees `d_private` and returns `errno`, so no double close or leak. The access-mode checks (`EBADF`, write-only refused) come before the duplicate. Reviewed fix 1 (EBADF instead of EROFS) is correct against `ntfs_device_mount()`'s retry on `EROFS`.
- Order of operations: `ntfs_open()` (line 4455) runs before `fuse_mount()` (reached later) and before `daemon()` (line 4301), so `FD_CLOEXEC` on N is set before libfuse can spawn a helper.
- `inherited_blkdev()` relaxes the unprivileged block-device refusal only for an inherited descriptor; a block device by path is still refused (R5, exit 19).
- Nothing new missed by the earlier review. Observations, none a defect: (1) any open descriptor number >= 3 is accepted as a device, so the daemon's `argv_check()` rule 1 (decimal 3..255, one fixed N) is the real control, and N must never equal another descriptor of the worker (for example the patch 0006 error channel); worth one sentence in ARCHITECTURE 3.3 or the T-M4-01 acceptance. (2) `lowntfs-3g` is unpatched and must not ship (stated in the patch header and README; the packaging task should make sure it is not shipped, and I did not check what the build installs). (3) The patch header carries diff timestamps (`2026-11-14 12:14` and `12:32`), cosmetic. (4) The library is patched, so `ntfsfix`, `mkntfs` and the probe also accept `/dev/fd/N`; stated in the header.
