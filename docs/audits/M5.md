## 0. Verdict

**BLOCKED. This is a defect list. The M5 exit gate is not met. None of 5.1 to 5.7 has a result file under `tests/results/` that covers a commit, and 5.8 was not done.**

As the owner expected, the long runs, the full `ci-local.sh` run on the gate commit and the hardware session were not done. The point that matters more is this: if those runs were made today, the gate machinery could still report a false pass. I found two High defects in the gate rule:

- `--verify-result --require-env host,A,B` accepts any stage that was skipped with a note. A `--quick` run, in which ASan, the probe and volmark suites, the crash sweep, the daemon suites, the compat stage and every stress suite are skipped, therefore "covers" the gate. I showed this with a real `test-all.sh --env host --quick` result and with quick-shaped A and B results (M5-F01).
- The documented gate command does not require the stages that `ci-local.sh` runs itself (tsan, static-analysis, linux-build-test, fuzz-short, package). It also does not require any criterion case (`S-SOAK-01`, `S-PAR-01`, `S-LEAK-01`, `S-NOSPC-01`, `S-KILL-*`). The option that could require them, `--require-case`, is not documented (M5-F02).

The individual suites are mostly well made. Each one I read turns a violated condition into `fail`. Each has a negative control or an injected-fault seam that fails, and each is checked by a selftest that runs before the real run. A partial run is a `fail`, not a missing case. A timeout fails, and evidence that is not complete fails. The Medium findings are about how the results connect to the criteria and to a commit:

- Shortened runs pass under the criterion's own case ids (M5-F04).
- The criterion-length runs have no documented way into a result file that is tied to a commit, and the fuzz campaign records no commit at all (M5-F05).
- The performance generator reuses earlier explanations as they are (M5-F06).
- Pre-built engines and reused fixtures are not tied to the commit under test (M5-F07).
- The tests of the gate checker itself are not run by any stage (M5-F08).
- No M5 run of any kind is committed (M5-F03).

Finding counts: Critical 0, High 2, Medium 6, Low 5.

M4 Low findings: F-02, F-03, F-05 and F-06 are fixed in code, and each fix has unit tests that can fail (section 4). F-03 and F-06 keep a documented residual window that only root can use. F-04 stays as the accepted design. `docs/audits/M4.md` still lists F-02 to F-06 as open (M5-F13).

## 1. Findings

### High

**M5-F01. The gate rule accepts a result in which every long stage was skipped** (`scripts/ci-local.sh:400`; `scripts/ci-local.sh:44-45`; `docs/TEST_STRATEGY.md:489`, "pass, or skip with a note").
`verify_results` builds the set of stage cases each environment needs from `test-all.sh --env ENV --dry-run`. Then it accepts every one whose status is `pass` or `skip`: `missing = [c for c in need if status.get(c) not in ("pass", "skip")]`. A skip always has a note, because the validator (`report.py:114-115`) requires one and `aggregate` fills in `"skipped"` (`report.py:387-388`). So any skip passes the check. `test-all.sh --quick` and `--cases` record the heavy stages as `skip` with the notes "skipped by --quick" or "not selected by --cases" (`test-all.sh:191-204`, `run-suite.sh:249-301`).
Scenario (done in this audit): `scripts/test-all.sh --env host --quick --out <tmp>/2026-11-20-58777e6-host.json` wrote a clean result with `STAGE-HOST-BUILD-ASAN` and `STAGE-HOST-UNIT-ASAN` skipped. `ci-local.sh --verify-result <that file> --pre-commit --require-env host` printed `PASSED`. With A and B results shaped like `--quick` runs (B: `fixtures`, `compat`, `daemon` and all five `stress-*` skipped "by --quick"; A: `unit-probe`, `unit-volmark` and `stress-crashsweep` skipped), `--require-env host,A,B` also printed `PASSED`. `--pre-commit` only bypasses the path and committed-content checks. Those checks would pass too once the files are committed. So a commit that holds three quick results is "covered" for criterion 5.7. Criterion 5.7, however, requires a full local CI run.
Fix: in gate mode, require `pass` for every planned stage. Allow a named, short list of skips that are skips by design (host `harness` "they run in --env B", host `stress` "none registered") and nothing else. Also record the run mode in the result (for example a case `STAGE-<ENV>-MODE` with note `full`, `quick` or `cases=...`) and reject any mode other than `full`. Amend TEST_STRATEGY section 10 to match.

**M5-F02. The documented gate command requires neither the stages that `ci-local.sh` runs itself nor any criterion case** (`scripts/ci-local.sh:9-10`, usage without `--require-case`; `:111-113`; `:398-399`; `docs/TEST_STRATEGY.md:489`).
TEST_STRATEGY section 10 says the files must hold a stage case "for each stage `ci-local.sh` runs itself", and gives the command `scripts/ci-local.sh --verify-result <file>... --require-env host,A,B`. That command requires only the `test-all.sh` plan stages. `STAGE-HOST-TSAN`, `STAGE-HOST-STATIC-ANALYSIS`, `STAGE-A-LINUX-BUILD-TEST`, `STAGE-A-FUZZ-SHORT` and `STAGE-B-PACKAGE` (the `-ci` files) are required only through `--require-case`. Full mode passes that option internally (`:450-461`, `:765`), but the usage text does not list it and the documented gate command does not use it. In my experiment the three files had no `-ci` file at all, and the check still printed `PASSED`. The check also requires no case that the criteria name. If `S-NOSPC-01` or the `I-*` cases in B are a `skip` (`harness/volume.py:197-203`: "macFUSE is not installed in the guest", tools missing), or if a stress result is missing, the gate is still met. That holds as long as one case passed.
Fix: make `--require-env` imply the `-ci` stage cases of each environment, exactly as full mode computes them. Document `--require-case`. Add a per-milestone list of the cases that must `pass` (M5: `S-SOAK-01`, `S-PAR-01`, `S-LEAK-01`, `S-NOSPC-01`, `S-KILL-01..04` and their controls, with the criterion parameters, see M5-F04), and make the gate check read that list.

**M5-F04. Shortened runs pass under the criterion's case ids; three suites do not even say that the run was short** (`tests/stress/soak/mix_result.py:236-237`; `tests/stress/leaks/classify.py:343-346, 378`; `tests/stress/kill/result.py:88-92`; `tests/stress/disconnect/disc_result.py:100-101`).

They write `S-SOAK-01`, `S-PAR-01`, `S-LEAK-01`, `S-KILL-01..04` and `S-DISC-01..04` as `pass`. Soak and parallel put "shortened run, not criterion 5.2/5.3" in the note (good, but only in the note). **M5-F05. The criterion-length runs have no documented way into a result file under `tests/results/` that is tied to a commit, and the fuzz campaign records no commit at all** (`tests/stress/*/README.md`; `tests/perf/README.md`; `tests/fuzz/campaign/run.sh:164-166`, `triage.py`).
The criterion runs are separate commands (`run.sh --out DIR --full`, `--reps 20`, `--iterations 50`, `tests/perf/run.sh --env A|B --out DIR`, `tests/fuzz/campaign/run.sh --budget-hours 8`). They write `DIR/result.json`, or for the fuzz campaign `build/fuzz/campaign/<stamp>/triage.{md,tsv}` (git-ignored). Only the registered short defaults reach `tests/results/` through `test-all.sh`. A standalone `result.json` carries `git_sha` and `dirty_tree`, but it is not named by the rule, its evidence paths are relative to `DIR`, and no command is documented that adopts it. The fuzz campaign output contains no `git_sha` and no dirty flag. Section 4 of `docs/SECURITY_FINDINGS.md` says to copy `triage.md` into the document, so the 8 CPU-hour result for criterion "every crash classified" can never be tied to the commit that was fuzzed.
Fix: add `test-all.sh --env B --stress-mode full` (or a `report.py adopt --env B --dir DIR` that builds a correctly named result with copied evidence). Make the fuzz campaign write an `ntfsmac-test-result/1` file with `F-*` cases, `git_sha` and `dirty_tree`, and refuse a dirty tree unless `--allow-dirty` is given.

**M5-F06. The performance generator reuses the explanations that are already in `docs/PERFORMANCE.md` for whatever the criterion run flags, and it does not check that A and B are the same commit** (`tests/perf/report.py:97-122`, `:291-301`, `:156-168`; `docs/PERFORMANCE.md` "Explanations").
`main` calls `render(load(a), load(b), keep_explanations(a.out))`. With `--out docs/PERFORMANCE.md` (the documented command), every `- **phase**:` entry already there is kept and printed for that phase if it is flagged again. The committed file already holds entries for `seq_write`, `seq_read`, `rnd_write` and `rnd_read` that were written about the smoke run ("Smoke, not criterion: ... after"). If the criterion run flags those phases above 2x, they show as explained with no person writing anything. That meets the letter of criterion 5.6 ("regressions above 2x are explained") with stale text. A placeholder does not make the generator exit non-zero. `render` marks the comparison invalid for different parameters, a different image or a dirty tree, but not for different `git_sha` values of A and B, or for a commit that is not the gate commit.
Fix: key each explanation to the commit pair it was written for, and print carried-over text as "from run <sha>, not re-confirmed". Exit 1 while any flagged phase has a placeholder or an unconfirmed carry-over. Mark the comparison invalid when A and B differ in `git_sha`.

**M5-F07. A pre-built engine and reused fixtures are not tied to the commit under test** (`tests/integration/daemon/dmn_vm.sh:141-143`; `tests/stress/soak/mix_host.sh:139-142`; `tests/stress/disconnect/run.sh`, `tests/stress/kill/run.sh` (`--deps-tar`); `scripts/test-all.sh:371-373`, `vm/macos/run-suite.sh:270-283` (`--fixtures DIR`)).
`dmn_vm.sh --deps-tar FILE` installs `~/ntfsmac/deps` from the tar "(no build)" without comparing it with the current patch series and tarball. The soak, parallel, disconnect and kill suites accept the option and pass it on. Their `result.json` then records the checkout's `git_sha` as the tested commit, while the worker in the guest may come from an older patch series. In contrast, the leak suite only seeds the build and lets `build-ntfs3g.sh` rebuild when its stamp differs (`tests/stress/leaks/run.sh:101-116`). The two-hour and six-hour criterion runs are exactly where `--deps-tar` saves time. In the same way, `test-all.sh --env B --fixtures DIR` records `fixtures` as `skip` "reusing DIR" and the gate accepts it (M5-F01), but the images may have come from any generator version.
Fix: store the `build-ntfs3g.sh` stamp key in the deps tar and refuse a tar whose key differs (or always run `build-ntfs3g.sh` after seeding, as the leak suite does). Record the deps-tar and fixture hashes in `meta.txt` and in the case note.

**M5-F08. The tests of the gate checker are not run by any stage** (`tests/unit/ci/test_ci_local.sh`, `test_ci_local_full.sh:7`, "Not registered with CTest"; `CMakeLists.txt:38-65`).
The rules of `--verify-result` and of full mode are the thing every milestone gate depends on. Their tests are registered with no ctest test and run in no stage of `ci-local.sh` or `test-all.sh`. Both pass when run by hand (this audit). A change that breaks `--verify-result`, for example one that accepts a failed case, is caught only if someone remembers to run the scripts. The stress classifiers have the same gap in a milder form: their selftests run only at the start of a VM run, not in ctest. `fuzz.campaign_tools` shows that the pattern is easy to follow.
Fix: register both CI scripts and the seven classifier selftests as ctest tests (they need no VM).

**M5-F10. Negative controls and fault seams can be switched off or left out of the record** (`tests/stress/soak/mix_host.sh:72` `--controls ""`; `tests/stress/disconnect/run.sh:20-21, 137`; `tests/stress/kill/run.sh` `--no-control`/`KILL_CONTROL=0`; `tests/stress/kill/result.py:108`).

**M5-F11. The README status table and the hardware sign-off line are not bound to a commit, and the table has no row for any M5 criterion** (`tests/harness/report.py:509-519`, `:536-545`; `tests/harness/features.json`; `docs/HARDWARE_TEST_PROTOCOL.md:683-685`).
