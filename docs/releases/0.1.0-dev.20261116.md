# ntfs-macos 0.1.0-dev.20261116 (developer preview, superseded)

> [!WARNING]
> **Superseded on 2026-11-27. Do not install this package.**
>
> An independent audit of the installer ([`docs/audits/M6.md`](../audits/M6.md), finding M6-F02) found that an upgrade
> from this package can make the macOS Installer delete, as root, files in
> `/usr/local/share/doc/ntfs-macos`, a directory that a user may control (for example a Homebrew
> `/usr/local` moved from an Intel Mac). It also found that the uninstaller shipped here follows
> symbolic links. Later packages use a new identifier, `org.ntfs-macos.pkg.v2`, and check every
> directory on the way to each path before they install or remove anything (PR #17, issue #6).
>
> There is no newer published package yet. Packages are built and tested locally (ADR-015); to
> build one, see "Build from source" in
> [docs/INSTALL.md](../INSTALL.md#build-from-source).
>
> **If you installed this package**, do not run its own `uninstall.sh`. Remove it with the current
> uninstaller from the repository instead:
>
> ```sh
> git clone https://github.com/kurok/ntfs-macos.git && cd ntfs-macos
> sudo sh packaging/uninstall.sh --dry-run   # shows what it would remove
> sudo sh packaging/uninstall.sh
> ```
>
> It removes the receipt `org.ntfs-macos.pkg` and the files of this package (its documents in
> `/usr/local/share/doc/ntfs-macos` included). It never removes anything below a directory that is
> not root-only (a symbolic link, or a directory not owned by root or writable by other users): if
> such a directory is above an installed program, it stops before removing anything; if it is above
> one of the old documents, it keeps that file. Either way it names the directory, exits with
> status 1 and keeps the old receipt: fix the named directory and run it again. Installing a later
> package over this one also removes it, in the same safe way.

Tag `v0.1.0-dev.20261116` on commit `91358db`, the commit the package was built from (`91358db1a2edee05b6a0cfa625de696daba88181`,
2026-11-16). GitHub pre-release.

> **This build cannot mount an NTFS volume.** It is the first package of the project, published so
> that the packaging, the installer checks and the uninstaller can be tried. Automatic mounting, the
> daemon, the `ntfsmac` command and Finder integration come with Milestone 4. Do not use the tools
> on a drive that holds data you care about.

## Contents

- `ntfsmac-worker`: NTFS-3G 2026.9.28 with the patch series 0003 to 0013
  (`third_party/patches/ntfs-3g/`; 0004 is a test-only fault layer that this build does not enable), linked against macFUSE's libfuse 2.9.9 (not bundled).
- `ntfsmac-probe`: the read-only safety probe. It reports whether a volume is clean, dirty,
  hibernated (Fast Startup), BitLocker-encrypted or damaged, and so whether it may be mounted
  read/write.
- `ntfsmac-volmark`: sets and clears the on-disk marker that records an open read/write session.
- `mkntfs`, `ntfsfix`, `ntfsinfo`, `ntfslabel` from ntfsprogs 2026.9.28.

The patch series includes local fixes for three memory-safety defects in NTFS-3G that were
reported privately to the NTFS-3G maintainers on 2026-11-16 (ADR-026). The fixes will be removed
once a fixed NTFS-3G release is used.

## Tested

- Local CI: build and 20 unit tests on the build Mac.
- Milestone 3 gate suites at `a97f472` (same product code): Environment A (Linux container)
  48 of 48 integration tests; Environment B (macOS 27 VM, macFUSE FSKit) 67 of 68, with the one
  error an intermittent `umount` "Resource busy" that passed in three repeat runs; probe, volmark
  and host unit suites; fuzzing (one hour per target, no crash).
- Release pipeline: the package was built in a clean macOS 27 VM, installed in a second clean VM,
  each installed binary was started once, and `uninstall.sh` left no file and no receipt.

## Known limits

- No mounting: there is no daemon, no automount and no Finder integration yet.
- Unsigned: Gatekeeper blocks a double-click; install with `sudo installer` (see INSTALL.md).
- Apple Silicon and macOS 27 or newer only.
- Not tested on physical drives.
